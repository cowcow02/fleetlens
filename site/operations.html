Fleetlens / Operations

Keep the local loop healthy.

Fleetlens has two local processes and one state directory. Most operational questions can be answered without touching the transcript files.

Lifecycle

Server and daemon are separate, but start together.

The common path is one command; the advanced path lets power users manage the pieces independently.

Start

fleetlens start

Ensures the current web bundle is running, then starts the usage and sync worker unless --no-daemon is supplied.

Inspect

fleetlens status

Shows the server, daemon, and latest snapshot in one glance. Use daemon logs for provider or sync errors.

Stop

fleetlens stop

Stops the web server and daemon. fleetlens daemon stop stops only the worker.

State directory

~/.cclens is Fleetlens's local control plane.

Use CCLENS_HOME to isolate this state for another workspace, test run, or demo environment.

Build from source

git clone https://github.com/cowcow02/fleetlens.git
cd fleetlens
pnpm install
pnpm typecheck
pnpm test
pnpm build

The published CLI bundles the web standalone output. When building the CLI flow manually:

NEXT_OUTPUT=standalone pnpm build
node scripts/prepare-cli.mjs
node packages/cli/dist/index.js start
Verification rule

Use the repository's existing running dev server for smoke verification where possible. The canonical commands are pnpm typecheck, pnpm test, and pnpm verify.
