Fleetlens / Privacy

Local by default. Explicit when shared.

Fleetlens is designed so a useful dashboard does not require uploading transcripts. Team Edition exists for rollups, not raw conversation storage.

Two boundaries

What stays local, what can move.

The local process can inspect more than the server ever receives. That distinction is visible in the product's Team page and sync payload types.

Local Edition

No Fleetlens account required

The local dashboard runs on localhost and reads the agent roots on the same machine. Its only external calls are the provider requests needed for usage tracking and the local model calls you explicitly enable.

Team Edition

Pairing is an explicit opt-in

A member must run fleetlens team join and finish project selection before the daemon sends team payloads. The Team page exposes the current scope and last push state.

Operational responsibilities

  • Local users control their machine state, provider credentials, ~/.cclens, and selected sync projects.
  • Team admins control the server URL, Postgres database, encryption key, invite policy, staff access, and retention choices.
  • Provider auth remains provider auth. Fleetlens reads existing local credentials or configured keys and does not replace provider login.

Before opening a public issue

Remove OAuth tokens, invite tokens, bearer tokens, absolute paths, repository names, prompt text, and assistant output from logs or screenshots. Useful diagnostics usually include the Fleetlens version, command, route, and a redacted daemon error.

Privacy is a product invariant, not just a deployment setting.

The parser and entry layers are intentionally separated from filesystem and network concerns so downstream consumers can operate on derived capsules and aggregates.
