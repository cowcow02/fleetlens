# Multi-use invite links for team edition

**Date:** 2026-05-21
**Scope:** `packages/team-server`
**Status:** Approved, ready for implementation plan

## Problem

Team-edition invite links are single-use today. To onboard ten people, an admin
generates ten separate links. There is no UI to see active invites or revoke
one that leaked. Group managers face the same friction on
`/team/<slug>/groups/<group>/invite`.

The right primitive for "onboard the team" is a **share link** — one URL that
the whole team can use. We also want admins to restrict signup to specific
email domains so a leaked link still cannot pull in arbitrary outside accounts.

## Goals

1. Reusable share links, one per `(role, group_set)` config per team.
2. Active-links list with revoke, on both the admin settings page and the
   group-manager invite page (filtered to the manager's scope).
3. Single migration consolidates pre-upgrade invites down to the new model
   without leaving broken half-states.
4. Per-team email-domain allowlist enforced at signup time.

## Non-goals

- Per-link domain overrides (defer; team-level is enough).
- Usage caps (`max_uses`). Unlimited; revoke and regenerate if a link leaks.
- "Never expires" option. Defer to a later iteration.
- Reworking the single-use email-scoped invite path. It stays as-is for one-off
  invites; no UI changes required in this scope beyond moving it into a
  secondary section.

## Data model

### `invites` table changes (extends existing)

| Column | Type | Notes |
|---|---|---|
| `token` | `text` | Plaintext invite token. Nullable for back-compat during upgrade window. New rows always populate it. |
| `revoked_at` | `timestamptz` | Nullable. Replaces `used_at` as the redeemable-or-not signal. |
| `label` | `text` | Nullable. Optional human name; defaults to autogenerated in UI. |

`token_hash` is kept (token lookup still happens by `sha256(plaintext)`); the
`token` column exists so the admin UI can re-display the URL without
regeneration.

`used_at` stays for one release per expand/contract: code stops reading it but
still writes it for legacy compatibility. A follow-up release drops it.

The single-use vs. multi-use distinction is **implicit**:
- `email IS NOT NULL` → single-use. `redeemInvite` sets `revoked_at = now()`
  on success.
- `email IS NULL` → multi-use share link. `redeemInvite` leaves `revoked_at`
  alone; only an explicit admin/manager revoke clears it.

### `teams` table change

| Column | Type | Notes |
|---|---|---|
| `allowed_signup_domains` | `text[] NOT NULL DEFAULT '{}'` | Lowercase domain strings, no leading `@`. Empty array = no restriction (today's behavior). |

## Lookup and redemption

`lookupInvite` query becomes:

```sql
SELECT ... FROM invites
WHERE token_hash = $1
  AND revoked_at IS NULL
  AND expires_at > now()
```

`redeemInvite`:
- If `invite.email IS NOT NULL`: in the same transaction, `UPDATE invites SET revoked_at = now() WHERE id = $1` after the membership upsert.
- Otherwise: no `invites` mutation. The `member.join` event row already exists
  with `payload.inviteId`, which is the source of truth for the redemption
  count shown in the active-links UI.

Redemption count for a given invite, used in the list UI:
```sql
SELECT count(*) FROM events
WHERE action = 'member.join'
  AND payload->>'inviteId' = $1
```

## Consolidation migration

Runs as part of the schema migration that adds the new columns. One
statement, no filtering:

```sql
UPDATE invites SET revoked_at = now() WHERE revoked_at IS NULL;
```

Every pre-upgrade invite — multi-use, single-use, email-scoped, or not — is
revoked. The "1 per config" rule then applies prospectively from a clean
slate.

Why blanket-revoke everything rather than keep most-recent or preserve
email-scoped: pre-upgrade rows have only `token_hash`, so the new admin UI
cannot display a Copy button for them; keeping them around as hash-only
zombies creates a confusing UX. Adoption is still small enough that the
one-time cost of re-sending any in-flight invites is negligible, and a fully
uniform "all old links revoked" rule is simpler to implement, document, and
reason about than a partial preservation rule.

A one-time banner on the settings page after upgrade ("Invite links were
reset to support multi-use — recreate as needed") covers the comms.

## Domain allowlist

Enforced at one place: `packages/team-server/src/app/api/auth/signup/route.ts`,
after the body is parsed and the `email` extracted, before
`createFirstOrSubsequentUser`:

```ts
if (invite) {
  const team = await loadTeamBasics(invite.team_id, pool);
  const domains = team.allowed_signup_domains;
  const emailDomain = email.split("@")[1]?.toLowerCase();
  if (domains.length > 0 && !domains.includes(emailDomain)) {
    return NextResponse.json(
      { error: `Sign-up is restricted to: ${domains.map((d) => "@" + d).join(", ")}` },
      { status: 403 },
    );
  }
}
```

Applies to:
- Invite-redemption signups (both new and existing users — though existing
  members hitting their own team's invite are already members, so the check
  doesn't bite them in practice).
- Open public signup, if `allow_public_signup = true` for the team.

Does **not** apply to first-user bootstrap (`promotedToStaff` path) — there's
no team yet.

Existing memberships pre-dating a tightened allowlist are untouched. The
allowlist is a *gate at the door*, not a re-validation of who is already
inside.

## UI

### Admin settings: `/team/<slug>/settings`

The existing "+ Member invite / + Admin invite" buttons in
`components/settings-panel.tsx` are replaced by two stacked sections:

**Active invite links** — table of multi-use (`email IS NULL`) un-revoked
un-expired invites for this team:

| Label | Role | Groups | Created by | Expires | Redemptions | |
|---|---|---|---|---|---|---|
| Q2 hires | member | Engineering, Infra | charlie | in 84d | 7 | Copy · Revoke |
| (default member) | member | — | charlie | in 90d | 23 | Copy · Revoke |

`Copy` puts the URL on the clipboard from the `token` column. `Revoke` sets
`revoked_at = now()` and re-fetches.

Below the table: **+ New link** opens an inline form (role select,
multi-select group chips, optional label, expiry days defaulting to 90). If
the user submits a `(role, group_set)` config that already has an active link,
the API returns 409 with `{ error: "An active link already exists for this
configuration. Revoke it first." }` and the form surfaces that inline.

**Single-use email invites** — secondary section, collapsed by default.
Mostly the same UX as today for one-off email-scoped invites. Not in scope to
rework, just visually demoted.

**Sign-up policy** — new subsection, single comma-separated text input
labelled "Allowed email domains" with the placeholder
`acme.com, acme.io`. Splits on comma, trims, lowercases, strips leading `@`.
Empty saves as `[]`. Help text: "Leave empty to allow any email domain. New
sign-ups via invite or public signup must match one of these domains."

### Group manager: `/team/<slug>/groups/<group>/invite`

Same active-links table model, scoped to links whose `group_ids` is a subset
of the manager's managed-group set. Admins/staff see all team links here too.
"+ New link" pre-selects the current group with the same locked-in chip
treatment as today (`ManagerInviteForm` already does this).

Manager revoke permission: a manager can revoke any link whose `group_ids` is
a subset of their managed groups. Admins/staff can revoke any link in the
team.

## API changes

### `POST /api/team/invites` (admin, existing)

- Reject with 409 if an active link with the same `(team_id, role, sorted group_ids, email IS NULL)` already exists.
- Accept new optional `label` and `expiresInDays` (default 90).
- Response shape stays the same; `tokenPlaintext` is still returned for
  immediate copy, and is also retrievable later from the list endpoint below.

### `POST /api/team/[slug]/groups/[group]/invite` (manager, existing)

Same dedup + label + expiry changes as above.

### `GET /api/team/[slug]/invites` (new)

Returns active multi-use invites for the team. Includes `token` (plaintext)
for display. Authz: admin or staff sees all; group manager sees those whose
`group_ids` is a subset of their managed set.

```json
[
  {
    "id": "...",
    "label": "Q2 hires",
    "role": "member",
    "groupIds": ["..."],
    "groupNames": ["Engineering", "Infrastructure"],
    "createdBy": { "id": "...", "displayName": "charlie" },
    "createdAt": "...",
    "expiresAt": "...",
    "token": "iv_...",
    "joinUrl": "https://.../signup?invite=iv_...",
    "redemptionCount": 7
  }
]
```

### `POST /api/team/[slug]/invites/[id]/revoke` (new)

Sets `revoked_at = now()`. Authz mirrors the list endpoint. Emits a
`member.invite.revoke` event with `{ inviteId }`.

### `PATCH /api/team/[slug]` (existing or new)

Adds support for updating `allowed_signup_domains`. Validates each entry as a
plausible domain (`/^[a-z0-9.-]+\.[a-z]{2,}$/i` after lowercasing).

## Defaults and naming

- `max_uses`: no column. Unlimited.
- Default expiry: 90 days. Override 1–365 in the form.
- Token format: unchanged (`iv_` + 32-hex).
- Terminology: "Invite link" everywhere in the multi-use UI. "Email invite"
  for the single-use secondary section.

## Migration ordering (expand / contract)

Two releases.

**Release N (this spec):**
- `ALTER TABLE invites ADD COLUMN token text` (nullable)
- `ALTER TABLE invites ADD COLUMN revoked_at timestamptz` (nullable)
- `ALTER TABLE invites ADD COLUMN label text` (nullable)
- `ALTER TABLE teams ADD COLUMN allowed_signup_domains text[] NOT NULL DEFAULT '{}'`
- Consolidation: `UPDATE invites SET revoked_at = now() WHERE revoked_at IS NULL` (blanket-revoke every pre-upgrade invite, single-use and multi-use alike)
- Code reads `revoked_at` as the gate; still writes `used_at` on single-use redemption for back-compat; writes `revoked_at` on every redemption that consumes a single-use invite, and on every admin/manager revoke.

**Release N+1:**
- `ALTER TABLE invites DROP COLUMN used_at`
- Code stops writing `used_at`.

The token plaintext column being nullable is permanent — historic rows that
ever existed without it must not be re-displayable, only revoke-able.
